# Komet 3.0.0

Changes since **Komet 2.0.0** for Vintage Story 1.22.

## Upgrading

- Replace the old Komet zip in your `Mods` folder with `komet_3.0.0.zip`. Remove any separate `kometsdk_*.zip` from
  the 3.0 previews. Shader Studio, its Modding pages and its templates ship in the main zip.
- A fresh renderer setting starts with **Vulkan-only (Lean)**. Komet keeps an explicit renderer choice and falls back
  to OpenGL when Vulkan cannot start. You can select OpenGL yourself or use **Try Vulkan again** under
  **Komet › Overview › Renderer**. A recorded Vulkan failure applies to the Komet version that encountered it.
- Press **K** for the details and frame cards, **Ctrl+K** for the dockable HUD window and **Ctrl+F8** for Shader Studio.
  In-game hints show your own bindings.

## Rendering and performance

- The Vulkan-only renderer runs on Linux and Windows, with shaderc bundled for Windows. Lean mode saves video memory
  by keeping large world buffers and textures in Vulkan. Komet warms up known pipelines and reports draws it cannot
  port.
- Batched GPU occlusion culling drops hidden terrain before drawing it. The Render tab and details card show how many
  triangles the GPU actually draws beside the count submitted by the game. Empty terrain pools and unused Vulkan
  buffer memory can be freed.
- Distant terrain and foliage simplify at configurable screen sizes. Nearby chunks regain detail first, and the
  transition spreads across chunk columns. This release also fixes visible chunk borders and water seams.
- Chunk upload and tessellation budgets keep the world loading while leaving room for frames. An upload limit of zero
  leaves the priority queue to the game. More chunk data can stay packed in RAM, including on the singleplayer server.
- Sounds decode on first use, equal animation keyframes and attribute values share storage, and the GPU culling buffer
  grows on demand. OpenGL can reuse unchanged shader programs from its binary cache. Vulkan starts from shader source
  when it needs to port a program.
- Vulkan fixes include OpenGL fallback when a swapchain cannot be created, terrain recovery after switching renderers,
  correct handling of 3D textures and `sampler3D`, and support for array sizes declared with `const int`.
- Fast Map's atlas updates reach Vulkan. Komet's cooking optimisation yields to A Culinary Artillery when both
  replace the same ingredient match.

## Settings and HUD

- The full-screen settings menu adds the **Pragmatic** and **Vintage** styles, a **Favorites** tab, and a combined
  **Help and Modding** tab with a page tree and clickable glossary. It remembers the last page and uses the game font
  where a style lacks the characters for your language.
- The **Mods** tab hosts registered settings pages and supported ConfigLib controls. Client and server settings are
  separate, and changing server settings in multiplayer requires the game's `controlserver` privilege. In developer
  mode, the **Developer** tab shows Compatibility, Connected mods and Render debug.
- The overlay, details card and frame card snap to a grid and remember their positions. The frame card shows the
  latest spike and its cause. The dockable HUD window brings rendering, threads, logs, the debug protocol and the
  inspector together. Captures can include thread allocations, lock waits and per-frame CSV data.

## Shader Studio

- Edit shader projects in game with a file tree, completion, search and replace, diagnostics for both renderers,
  history, autosave recovery, and side-by-side comparisons with the original. Preview the live frame, inspect render
  targets and pixels, or use the separate 3D preview. Projects can be exported as mods.
- A failed shader build keeps the last working result. A tab stays open when saving fails, and an untouched project
  copy leaves the installed shader in place. The workbench holds mouse and keyboard input even while **Show the game**
  is held, so the preview cannot send a click through to the world.
- The **Active shaders** page shows which packs and shader mods are running, their renderer, and port diagnostics.
  Shader mods run by default. Komet can switch their shader code on and off in-world, and preserves the systems of
  content mods and required dependencies, including mods such as Primitive Survival and Rivers.

## For mod authors

**KAPI 1.0 replaces the 2.x C# API.** Reference `Komet.Core.dll`, import `Komet.Api`, and call
`Kapi.Connect(this, "1.0")` in `StartClientSide`. The connection belongs to the current world. Keep a fallback when
Komet is absent, the connection is refused, or a registration reports that it is inactive.

| Komet 2.0.0 | KAPI 1.0 |
| --- | --- |
| `KometOptions` pages | `komet.Options.Page(...)` |
| `KometFeatures` registrations and holds | `komet.Features` and `KapiFeature` |

- The connection also exposes shader defines, uniforms and passes, mod timings, and menu styles.
- `komet.Rendering.AddStep(...)` registers a step at a named render stage on either renderer. The **Connected mods**
  page shows registrations, timings and errors.
- Mods can declare settings and shader passes in `assets/<modid>/config/komet.json`. Shader packs can use `komet-shader.json`.
  See the [KAPI getting-started guide](../site/articles/getting-started.md) and the
  [render-step guide](../site/articles/render-steps.md).
